## DSC 3.4-preview Resource Demonstration

Steve demonstrated new DSC 3.4 Preview 1 resources for Windows environment variables, Group Policy
administrative templates, and file content, including export, validation, and hashing capabilities;
he also described a coming file-copy resource.

- Environment Variables: Steve demonstrated Microsoft.Windows/EnvironmentVariable and
  EnvironmentVariableList, which manage persistent user or machine environment variables stored in
  the Windows registry. The example retrieved the machine-level PSModulePath.
- Group Policy Adapter: The Microsoft Adapter Group Policy template resource adapts Windows ADMX
  administrative templates into DSC v3 resources. Steve showed that Windows PowerShell policy
  settings such as module logging and script-block logging can be represented and managed through
  DSC.
- File Content Resource: The Microsoft.FileSystem.File/Content resource reads file contents as a
  string and supports get, set, test, and export operations. Steve used it against a .gitignore file
  and showed that the exported state can include SHA-256 and SHA-512 hashes to verify whether the
  file matches the expected content.
- Export Fix: Steve said the export operation had a defect in Preview 1 that he had already fixed,
  with the correction planned for Preview 2. He encouraged users to test the new resources because
  practical testing had already exposed an issue during development.
- Future File Copy: In response to Ryan's question, Steve clarified that an exported JSON
  configuration can be applied on another computer to recreate the same file content and path. A
  future file-copy resource will instead support specifying a source file, such as one on a network
  share, and a destination path; that resource does not yet exist.

## Community Demo - Microsoft365DSC Class-Based Conversion

Fabien reported that Microsoft365DSC converted more than 530 script-based DSC resources to
class-based resources, explaining the architectural changes, compatibility work, automation, and
performance mitigations required for the migration.

- Migration Scope: Fabien said all approximately 535 Microsoft365DSC script-based resources had been
  converted to class-based resources. The migration removed the separate schema.mof files, moved
  resource properties into the PowerShell module classes, and retained property descriptions through
  System.ComponentModel.Description attributes.
- Resource Structure: The former model repeated parameter blocks across Get-TargetResource,
  Set-TargetResource, and Test-TargetResource functions. In the class-based model, properties are
  defined once, Get returns a typed class instance, Set returns void, and Test delegates common
  behavior to the shared M365DSCResourceBase class.
- Bound Parameter Compatibility: Fabien explained that script-based resources rely on
  PSBoundParameters, which has no direct class-based equivalent. Microsoft365DSC added
  ReadBoundParameters to read values from the class's CLR backing fields. This was necessary because
  the Windows Local Configuration Manager populates properties through reflection, causing direct
  property reads to return null in that scenario, while DSC v3 handled the properties correctly.
- Conversion Automation: The team used a large conversion script, with AI assistance, to automate
  much of the resource conversion. Fabien said defining the target architecture, base-resource
  approach, and conversion behavior took about a year of design and community discussion, while the
  automated conversion itself took roughly two to three months.
- Performance Mitigation: Fabien reported that importing the class-based module increased from
  roughly 1.5-2 seconds to 5-6 seconds, and placing all resources in one file could increase import
  time to 18-20 seconds. Nested modules and bucketing improved the result. Configuration compilation
  also became substantially slower because Import-DscResource is evaluated for each resource; the
  project therefore created custom compilation logic that removes the expensive import step and
  performs character substitutions before parsing. The implementation details are documented in a
  three-part blog series and the code is open source.
